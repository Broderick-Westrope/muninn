# Development

```bash
go build ./...
go test ./...
```

`go run . <command>` runs a local build. It won't take over the launchd schedule: `muninn sync` only reinstalls the agent when the binary the plist names has gone missing.

## The web UI

The UI in `internal/web/static` is plain ES modules and CSS, embedded into the binary with `go:embed`. The browser loads the modules directly, with no build step. The one exception is the syntax highlighter's vendored Shiki bundle (see below). The pieces with real logic (palette matching, the lookup lifecycle, selection and Enter handling, line-range parsing, the highlighter's markup and worker lifecycle) live in DOM-free modules, or run against fakes, so they can be tested without a browser.

Their tests are in `internal/web/static/_test/*.test.mjs`, which `go:embed` skips, so they are never served. `go test ./internal/web/` runs them through `node --test` when `node` 20.19+ or 22.7+ is on your `PATH`, and skips them otherwise. Those versions are the first that load `.js` files written as ES modules without a `package.json` `"type"` field. To run them directly:

```bash
node --test internal/web/static/_test/*.test.mjs
```

No CI workflow runs the tests, so a skip means they didn't run.

To try UI changes, rebuild and run `muninn web`. Embedded assets are served with `Cache-Control: no-cache`, so a reload picks up the new build.

### Syntax highlighting

Files in the 36 languages listed in `internal/web/static/languages.js` are highlighted in the browser by [Shiki](https://shiki.style), in a Web Worker. Every other language is highlighted on the server by chroma, which is also the fallback when Shiki can't colour a file. `plans/completed/design-2026-10-21-shiki-highlighting.md` explains the design.

Shiki is vendored as a prebuilt bundle in `internal/web/static/vendor/shiki`, generated by `tools/shiki` with Node and esbuild and committed, so `go build` needs neither. Regenerate it after changing `languages.js`, the Shiki version, or the theme tables in `tools/shiki/build.mjs`:

```bash
cd tools/shiki && npm ci && npm run build
```

The build also writes `vendor/shiki/THIRD_PARTY_NOTICES.md`, the licences of every bundled grammar and package. The UI tests check the bundle holds exactly the grammars `languages.js` picks, so a forgotten rebuild fails `go test`.

## Releases

Pushing a `v*` tag runs `.github/workflows/release.yaml`, which uses GoReleaser to:

- build `muninn` and `muninn-mcp-proxy` for macOS on arm64 and amd64
- publish a GitHub release with a changelog that leaves out `docs:` and `test:` commits
- update the formula in [Broderick-Westrope/homebrew-tap](https://github.com/Broderick-Westrope/homebrew-tap)

```bash
git tag vX.Y.Z
git push origin vX.Y.Z
```

Tags follow semver: bump the minor version for new features and the patch version for fixes. The workflow needs a `GH_PAT` secret with write access to this repo and the tap, since the default token can't push to another repo.
